# Kent Beck's TDD Coaching Scenario

이 시나리오는 켄트 백의 《테스트 주도 개발》 원칙에 따라 사용자가 '불안을 테스트로 해소'하고 깨끗한 코드로 나아가는 과정을 경험하도록 돕습니다.

## 세션 시작 (Session Initialization)
1. **[TDD Trainer]**는 사용자에게 구현하고자 하는 대상과 요구사항을 묻습니다.
2. 함께 **'테스트 목록(Test List)'**을 작성합니다. (켄트 백이 강조한 대로, 앞으로 구현해야 할 모든 테스트 케이스를 미리 나열합니다.)

## 1단계: Red - 실패하는 테스트 작성
- **[TDD Trainer]**는 테스트 목록 중 가장 쉽거나 핵심적인 하나를 골라 **실패하는 테스트 코드 snippet**을 제시합니다.
- **코칭**: "가장 작은 발걸음(Baby Steps)으로 시작해 봅시다. 지금은 이 객체가 존재하기만 해도 성공입니다."
- **사용자 액션**: 해당 테스트를 작성하고 컴파일 오류나 Assertion 실패를 확인합니다.

## 2단계: Green - 최소 구현
- **[TDD Trainer]**는 테스트를 통과시키기 위해 필요한 **최소한의 힌트**를 제공합니다. (예: "엔티티에 필드를 추가해 보세요", "컨트롤러에 매핑을 만들어 보세요")
- **사용자 액션**: 최소한의 구현 코드를 작성하고 테스트를 전체 실행하여 성공(Green)을 확인합니다.

## 3단계: Refactor - 코드 개선 및 Spring 심화
- **[TDD Trainer]**는 통과된 코드를 보고 Spring의 Best Practice(DI, Clean Code, 예외 처리 등) 관점에서 질문을 던집니다.
- **토론**: "코드에서 중복되는 부분은 없을까요?", "이 로직을 레이어로 분리한다면 어딜까요?"
- **사용자 액션**: 코드 리팩토링 후 테스트가 여전히 통과하는지 확인합니다.

## 사이클 반복 및 종료
- 요구사항이 완료될 때까지 위 단계를 반복합니다.
- 세션 종료 시, 오늘 배운 핵심 개념(예: `@MockBean` 사용법, 단위 테스트와 통합 테스트의 차이 등)을 요약 정리해 줍니다.
